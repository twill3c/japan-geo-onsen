# CNN の事前登録(loop_016 / 設計書 Phase 6 §32・§54)

**このファイルは、CNN を 1 度も学習させる前に書いて積む。** 結果の JSON
(`public/data/ai/cnn.json`)はこのファイルの SHA-256 を持ち、テストが一致を確かめる。

## 1. 何を確かめるのか

設計書 §32 は「十分なデータが得られた場合のみ、地形などをラスター化して CNN による画像的分類を検討する」とし、
§54 は Phase 6 として「CNN による地理空間分類を試行する」としている。

loop_013 の表形式モデル(Random Forest)は、都道府県ごとに分けた検証で ROC-AUC **0.686** だった
(`public/data/ai/baselines.json`)。そこで次の 2 つを確かめる。

1. **地点の周りの地形を画像として見ると、表の特徴量(標高・傾斜・局所起伏などの数値)より多くが分かるか**
2. **その上積みは、CNN を配る(ブラウザで推論する §38)手間に見合うか**

当てる問いは loop_013 と**同じ**である: **P12 に登録された地点が「温泉」の分類か、温泉以外の観光資源か**。
温泉が湧くかどうかではない(§33)。正例 1,320 点・負例 1,320 点も同じものを使う。

## 2. 画像の作り方

- 国土地理院の標高タイル(dem_png)**z14** から、地点を中心にした **64 × 64 画素**(北緯 36 度で約 490 m 四方)を切り出す
- 3 チャンネル:
  1. **相対標高** = (各画素の標高 − 画像の中央 4 画素の平均標高) ÷ 100 m
  2. **傾斜**(Horn 法・度 ÷ 45)
  3. **欠測の印**(海・無効値の画素 = 1。そこでは 1・2 チャンネルを 0 にする)
- 絶対標高は画像に入れない(表の特徴量として別に持つ)。**画像が見るのは形**である
- 地理院の地図(色付き)や地質図の画像は使わない(文字・記号・凡例の色が温泉の印を含みうるため)

## 3. モデルと学習

- **画像だけの CNN**: 畳み込み 3 段(16・32・64 チャンネル、各段 3×3 畳み込み → BatchNorm → ReLU → 2×2 最大値プーリング)
  → 全体平均プーリング → ドロップアウト 0.3 → 全結合 1 出力
- **画像 + 表の CNN**: 上の画像の要約(64 次元)に、loop_013 と同じ 8 特徴量(数値は学習側の分割で中央値補完・標準化、
  地質は one-hot)を連結してから全結合 2 段(32 → 1)
- 最適化: Adam(学習率 1e-3)・重み減衰 1e-4・バッチ 64・**30 エポック固定**(早期終了しない —— 検証側を見て止めると漏れる)
- 学習時だけ、画像を 90 度単位で回転・左右反転する(地形に北向きの意味を持たせない)
- 乱数の種は **3 つ**(20260916・20260917・20260918)。**合否は 3 つの平均で判定**し、ばらつきも出す
- ハイパーパラメータは上に書いた値で固定し、結果を見て調整しない

## 4. 評価の仕方

- loop_013 と**同じ都道府県ごとの 5 分割**(GroupKFold)。分割外の予測で ROC-AUC を計算する
- 比べる相手: loop_013 の Random Forest の都道府県分割 ROC-AUC(**0.686**。結果を見る前に固定した値)

## 5. 合否(ここを結果を見てから動かさない)

| ID | 条件 | 意味 |

## 6. 足りないデータ

画像が 64 × 64 すべて揃わない地点(タイルが取れない・画像の大半が海)は、学習から外さず**欠測の印**で扱う。
取れなかったタイルの数と、欠測画素の割合が 50% を超える地点の数を結果に書く。
